# Telegram Gift Sniper Bot

Бот-меню (aiogram 3) для управления юзер-аккаунтами (Pyrogram), которые
мониторят NFT-маркет подарков Telegram и автоматически покупают подарки
по заданным ценовым правилам.

## ⚠️ Важно прочитать

- Автоматизация покупок на маркете подарков через юзер-сессии (не через
  официальный Bot API) формально нарушает пользовательское соглашение
  Telegram — аккаунт может получить ограничение или бан. Это на твоей
  ответственности.
- Точные raw-методы (`payments.GetStarGifts`, `payments.GetResaleStarGifts`,
  `InputInvoiceStarGiftResale` и т.п., см. `bot/services/gift_sniper.py`)
  соответствуют официальной схеме Telegram на момент написания
  (см. https://core.telegram.org/api/gifts), но Telegram может менять
  номера конструкторов и поля — если покупка перестанет работать, нужно
  свериться со схемой и поправить raw-вызовы.
- Тестируй сначала на некритичном аккаунте с небольшим балансом звёзд.

## Переменные окружения (задаются на хостинге bothost)

| Переменная            | Описание                                                                 |
|-----------------------|---------------------------------------------------------------------------|
| `BOT_TOKEN`            | токен бота от @BotFather                                                 |
| `API_ID` / `API_HASH`  | с my.telegram.org, нужны для юзер-сессий Pyrogram                        |
| `ADMIN_ID`              | Telegram ID администратора (для него нет капчи/языка)                  |
| `SNIPE_MIN_PRICE`        | нижняя граница цены лота для автопокупки (по умолчанию 125)          |
| `SNIPE_MAX_PRICE`         | верхняя граница цены лота для автопокупки (по умолчанию 275)        |
| `POLL_INTERVAL`            | интервал опроса маркета в секундах (по умолчанию 5)                |
| `DB_PATH`                   | путь к файлу SQLite                                                |

⚠️ Аккаунт, который подключается в разделе "Аккаунты", должен **уже иметь
звёзды на балансе** — бот их не покупает и не пополняет, только тратит на
подарки. Перед каждой покупкой бот проверяет баланс через
`payments.GetStarsStatus` и пропускает лот, если звёзд не хватает.

Скопируй `.env.example` в `.env` и заполни (или задай переменные напрямую
в панели bothost — они читаются через `os.getenv` в `bot/config.py`).

## Запуск локально

```bash
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # и заполнить
python main.py
```

## Логика автопокупки (`bot/services/gift_sniper.py`)

Простое правило по диапазону цены — без истории и подстройки под рынок:

1. Каждые `POLL_INTERVAL` секунд получаем список подарков (`payments.GetStarGifts`).
2. Для подарков с активной перепродажей подтягиваем самый дешёвый лот
   (`payments.GetResaleStarGifts`, сортировка по цене).
3. Если цена этого лота попадает в диапазон
   `[SNIPE_MIN_PRICE, SNIPE_MAX_PRICE]` (по умолчанию 125–275⭐)
   включительно — бот покупает его немедленно.
4. Перед покупкой бот проверяет баланс звёзд на аккаунте
   (`payments.GetStarsStatus`) и пропускает лот, если звёзд не хватает —
   баланс должен быть уже пополнен пользователем заранее.
5. Подарки, помеченные пользователем как "игнор" (🔴 в разделе "Подарки"),
   пропускаются полностью.

Диапазон цены настраивается через `SNIPE_MIN_PRICE` / `SNIPE_MAX_PRICE` —
код менять не нужно.

## Что можно доработать

- Сейчас список подарков в разделе "Подарки" читается через первый
  добавленный аккаунт пользователя — если аккаунтов нет, показывается
  сообщение об ошибке.
- Хранение Pyrogram `.session` файлов — плоские файлы в `sessions/`.
  На проде стоит подумать о шифровании этой папки (это фактически ключи
  доступа к аккаунтам, а не только к боту).
- Ограничение на количество одновременных мониторингов, если аккаунтов
  станет много (сейчас каждый аккаунт — отдельная asyncio-задача с
  собственным поллингом раз в 5 секунд).
